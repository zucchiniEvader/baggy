# Desktop app

`desktop/` is a separate Go module (`github.com/spike/gobot/desktop`, `replace`d onto the repository root) so the core keeps no UI dependencies. It is a MyGo 0.3.6 app of native UI, drawn from Go with no web page; `go.mod` pins the `mygo` CLI as a Go tool, and goldmark parses markdown.

```
cd desktop
go tool mygo dev                           # builds, runs, relaunches on a change
go test ./...                              # views run in MyGo's offscreen Tester
GOBOT_RENDER=<folder> go test -run TestRender ./...   # writes group-light.png and group-dark.png
```

State is a `store` in `GOBOT_DATA` (default: the user config folder's `gobot`), seeded with Chef. Bots run on the providers added in Settings; with none, on the environment's (`connect.FromEnv`: `GOBOT_API`, `GOBOT_BASE_URL`, `GOBOT_API_KEY`, `GOBOT_MODEL`, or `ANTHROPIC_API_KEY`). A bot's tools are `shell`, `read_file`, `write_file`, `edit_file`, `find` and `grep` in its workspace, plus the team's and its memory's; failed model calls are retried (`agent.DefaultRetry`), the header reading "Retrying: …" meanwhile and the partial reply dropped.

## Icon and builds

`mygo.json` names the app gobot (`io.github.spike.gobot`); its icon is `resources/icon.png`, the art of `resources/icon-source.png` (a square with no transparency) in an 824 rounded square centered on a transparent 1024 canvas, the shape macOS expects of an app icon, so the Dock shows it as it is rather than inside a gray frame. `go tool mygo build` writes `build/darwin-arm64/gobot.app` (its `AppIcon.icns` made from the icon) and `gobot 0.1.0.dmg`; the binary embeds the icon too, the Dock's on macOS for a bare build and the About pane's.

## State and threads

Views are immediate: `app.root` builds the window every frame from the `app` struct, which belongs to the main thread. `team.Team` emits from its goroutines through `app.post` (the window's `Update`), so events apply on the main thread in order. Tests give `post` a channel and run it on the test goroutine.

Each opened chat has a `chatView`: rows built from its stored entries (`buildRows`), then kept current by events. A reply streams into a row keyed by its turn (`message_start`, deltas); its stored `entry` replaces that row with the final rows (text, thinking, a tool card per call); a tool entry fills the cards' results, and `tool_end` fills one as soon as it finishes; `removed` takes a passed turn's rows out. A chat not yet opened loads from the store when it is, so restarting the app restores every transcript.

## The window

The look follows AGENTS.md's design (after `../tsubomi`): `theme.go` holds the palette and sizes, `controls.go` every field, button, row, pill, pop-up and badge, `icons.go` the Lucide icons. The window has a hidden inset title bar 40 high with the traffic lights centered on it, the sidebar's vibrancy on macOS (a gray elsewhere), a minimum of 720×480, one instance (a second launch shows the first's window), and a native menu bar (Settings, New Bot, New Group, Toggle Sidebar ⌘⇧B, Toggle Info, Search Chats ⌘F, Command Palette ⌘K, Stop ⌘.).

- **Sidebar**: a title-bar row with the sidebar toggle and New (a native menu: New Bot…, New Group…), a search field filtering the chats, the chats grouped by when they were last active (Today, Yesterday, Previous 7 Days, …) as 28-high rounded rows (a DM's bot icon, or a group's, the title, a spinner while it works, a monospaced unread capsule), Settings at the foot with "No model set up" in orange when there is no provider. A chosen row is gray, and the accent only while the arrows, Home or End move the choice (a key sets the list's `keyboard` flag, a click and losing the focus clear it). It slides open and closed with a clip (200ms, none under Reduce Motion), its inner edge resizes it between 200 and 420, and dragging it under 120 closes it.
- **Title bar of the chat**: the title (13, 600) and a muted status that hides whole when it does not fit (who is working, "Retrying: …", a group's members), a model pill on a DM (a native menu of the provider's models and Edit Bot…), Tasks (a terminal icon and the count) while commands run, and the inspector's toggle.
- **The conversation**, at most 760 wide and centered: the user's messages in a neutral bubble on the right (with the quote they reply to, or "From X, via message_bot"); a bot's replies as markdown under its icon and name at the start of its turn; web searches as muted lines with a globe ("Searching…" with a spinner, then "Searched the web for “…”"); thinking closed under a "Thinking" line that opens it (when Show thinking is on); a run of one bot's tool calls as one card of rows (a disclosure arrow, the tool's icon and name, a monospaced summary such as the command, and a spinner, a green check, a red mark or "waiting for approval"), each opening on its arguments (a script for codemode) and result in code blocks, a running command's last lines shown as they come and a waiting call's Allow, Always Allow and Deny under it; an error as red words beside an alert icon on a gray row; notices centered and muted; "X is thinking…" pulsing while a turn has not streamed yet. A message's context menu has Reply above the editing commands. Thinking under 160 characters (`shortThought`) is not shown: a passing note is not worth a line. Messages run from the top, the list following the end as it grows. A failed reply reads in words a person reads (no model yet: "No model is set up yet. Add a provider in Settings, then retry."); the chat's last one offers Open Settings (while there is no provider) and Retry, which runs the chat again from its transcript (`team.Continue`), the failed reply left out of what the model reads. With no provider stored and none in the environment, an empty chat shows **Set up a model** in its place: a provider (DeepSeek through its Anthropic endpoint with web search, Anthropic, OpenAI on Responses, OpenRouter, Ollama, or Other with its protocol, base URL and models) and its key, and Start, which stores it as the default. An empty chat otherwise shows its bot's icon in a gray tile, "Hi, I'm X", its description's first line and a few suggestions; with no chat at all, a mark and New Bot….
- **Composer**: a card (radius 12) with the reply being written ("Replying to …", ✕), the images attached, the text (two to ten lines), and a footer: attach, a hint ("↩ Send · ⇧↩ New line", or "↩ Steer · ⌘↩ Interrupt" in a busy DM), Interrupt in a busy DM with a draft, and a round send button (the accent) that becomes stop (gray) while the chat works with nothing typed. Typing `@` opens a popover of the group's members (in a DM, the other bots) whose highlight is the accent, since it owns the keyboard; the arrows and Enter or Tab pick one, sent as a mention, and an `@Name` typed out that one bot answers to counts too. Images attach by pasting (⌘V with an image on the clipboard), dropping files on the card (which rings while they hover), or the paperclip (PNG, JPEG, GIF, WebP up to 5 MB).
- **Inspector** (the panel toggle, 280 wide): a DM's bot (its icon tile, name, provider and model, description, Edit… and Show Folder, its Routines, MEMORY.md and how much of it loads, what the chat cost and how full its last request was, Delete Bot in red); a group's name, size and description (Edit…), its members as rows with Owner as a capsule and a ⋯ menu (Make Owner, Edit Bot…, Remove from Chat), Add Bot (a native menu of the others), usage, Delete Group.
- **Sheets**: a 17 bold title over a muted line, fields in a form (gray-filled, borderless, ringed while focused), choices as native pop-ups, Cancel and the primary action at the bottom right. New/Edit Bot (name, a look chosen from a row of icons, description, provider, model, thinking), New/Edit Group (name, description, members as check rows) ; deletes ask in a native-style alert.
- **Settings** is a window of its own (⌘,, the menu, the sidebar's gear; one at a time, brought to the front when open, remembering its frame as `StateKey: "settings"`), laid out as macOS's System Settings: the panes in a vibrancy sidebar on the left (a list the arrows move through, accent only for the keys), the pane on the right under its title, settings as rows in cards (a title and a muted line on the left, the control on the right, hairlines between). **General**: the language (Follow System, English, 简体中文, applied at once, the menu bar made again), Show thinking, Keep running when closed. **Models** drills down as macOS's settings do into a network or an account: its first page is every provider as a row of a card (an icon tile, the name with a Default capsule, its models and protocol, a chevron; a context menu with Edit…, Make Default, Delete) and Add Provider…; a row (or Enter on the one the arrows are on) opens the provider's page, whose title bar reads "‹ Models / Name" (the chevron, Escape or ⌘[ go back). The page uses the pane's whole width (up to 620): who it is with Make Default (or Default), then Connection (name, protocol, base URL, the key with a show/hide eye), Models, and Features (the protocol's switches: web search, reasoning back, encrypted reasoning), each a row with its title on the left, the field on the right and a muted note under it. A bar kept in view under it has Delete (asked in an alert), Test Connection (one short request through `connect`: "Connected: model answered." or the server's error), and Save with Revert only while the form differs from what is stored ("Saved" otherwise), or Cancel and Create for a new one. **Commands**: what happens before a command (Run, Ask every time, Auto-review) and the Always Allow rules, each removable. **MCP Servers**: as below. **About**: the data folder and Show Folder. What changes there shows in the main window at once.
- **Command palette** (⌘K): a search field over the chats and commands, filtered as typed, the arrows moving an accent highlight since it owns the keyboard. ⌘N new bot, ⌘, Settings, ⌘1–9 a chat, ⌘⇧B the sidebar, ⌘F the search, Escape stops the chat shown.

## Approvals and preferences

The Commands preference says what happens before a shell command or a plugin tool its server does not mark read-only (a codemode script's too): Run, Ask every time, or Auto-review, where `team.Review` with the bot's own model lets through what is safe and only what it doubts waits, its reason shown. A waiting action shows on its card ("waiting for approval") and in a bar above the composer (a script's calls have no card), with Allow, Always Allow (keeps the exact command, or the plugin tool, as a rule in the settings) and Deny; a denial, or Stop, gives the bot `Declined`. Preferences sit in the store's settings: show thinking, commands, keep running when closed (closing hides the window; the tray icon's menu opens it again or quits; quitting itself, by ⌘Q, the Dock, the tray or SIGTERM, always closes it, since `OnBeforeQuit` marks the quit before windows are asked), the language (in Settings' General section: Follow System, English, or 简体中文 from `l10n_zh.go`, keyed by the English string `L` takes), and the sidebar's width and the inspector, saved as they change. The window remembers its size, position and maximized state (MyGo's `StateKey: "main"`).

The built app has been started against a scratch `GOBOT_DATA` and ran without errors; its views are checked in the offscreen Tester and by the rendered PNGs, not by hand.
